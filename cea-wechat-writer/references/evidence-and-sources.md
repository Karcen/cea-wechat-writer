# 证据与来源规范

## 来源优先级

1. 用户提供的原始论文、会议文件、机构文件或完整网页。
2. 论文出版社页面、DOI 页面、作者所在机构、会议主办方、招聘机构、期刊官网、政府或国际组织官网。
3. 可追溯的正式数据库或档案。
4. 其他媒体和二手材料只作线索，不单独支持高风险事实。

网页信息可能变化。记录访问日期，并在发布前复核日期、链接、岗位、指标和职务。

## `sources.md` 格式

```markdown
# 来源台账

## S1
- 类型：原始论文 / 官方网页 / 官方文件 / 用户说明 / 二手来源
- 标题：
- 作者或机构：
- 路径或 URL：
- 发布日期：
- 访问日期：
- 支持的事实：
  - 研究样本为……
  - 表 3 报告……
- 定位：第 12 页、表 3、Results 小节
- 状态：VERIFIED / NEEDS_REVIEW / CONFLICT / USER_OVERRIDE
- 备注：
```

每个来源编号必须唯一。路径使用绝对路径；网页使用可直接打开的 URL。

## 正文锚点

在重要事实所在段落末尾放隐藏锚点：

```markdown
研究样本覆盖2010—2022年。<!-- source:S1 -->
```

一个段落由多个来源支持时：

```markdown
……<!-- source:S1,S3 -->
```

锚点用于内部审校，正式转换平台格式时可统一移除。不得引用一个没有登记在 `sources.md` 的编号。

## 推断与解释

- 作者的解释写成“作者认为/研究提出”。
- 基于材料做出的编辑性推断写成“这意味着/可以理解为”，并在来源台账标记 `EDITORIAL_INFERENCE`。
- SDGs 可以依据研究主题提出建议，但在台账中标成“编辑映射”，不能伪装为论文作者声明。
- 不确定的作者简介、职务或中文译名使用 `NEEDS_REVIEW`，不补写看似合理的内容。

## 冲突处理

原文和官方网页冲突时：

1. 在台账记录两条来源及冲突内容；
2. 正文暂不采用争议信息，或用明确限定语并标记待确认；
3. 在 `qa-report.md` 生成 `BLOCK`；
4. 只有用户明确选择并承担风险后才能标记 `USER_OVERRIDE`。
