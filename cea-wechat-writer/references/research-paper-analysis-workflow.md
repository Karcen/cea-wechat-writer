# 两阶段研究级论文解读工作流

本文件只适用于“研究级论文解读”模式。公众号推文继续执行 `SKILL.md` 中的公众号写作流程。

## 目录

1. 输入与保存位置
2. 阶段 1 需求对齐
3. 阶段 2 准入条件
4. 三类论文材料的职责
5. 正式分析方法
6. 最终 Markdown 结构
7. 深度与表达要求
8. 交付前验证

## 1. 输入与保存位置

### 1.1 首轮只收集四个绝对路径

按顺序询问并回显：

1. **Skill 目录**：含 `SKILL.md` 的目录；若用户给出上级目录，则在其内部定位 `SKILL.md`。发现多个候选时让用户选择，不得擅自决定。
2. **论文 PDF**：原始论文 PDF 的绝对路径。
3. **论文 Markdown**：由同一份论文转换得到的 `.md` 文件绝对路径。
4. **论文 figures 目录**：从论文提取的图片目录绝对路径；确实没有时允许用户回复“无”。

如果当前调用已经明确指定 Skill 路径，回显该路径并请求确认即可，不要求用户再次粘贴。

询问论文 Markdown 时必须同时提示：

> 如果尚未生成论文 Markdown，请先使用 [MarkItDown Online](https://markitdown.online/) 将 PDF 转换为 Markdown，下载到本地后提供 `.md` 文件的绝对路径。PDF 涉及未公开、受版权或保密限制的内容时，请先确认是否允许上传第三方网站。

不得替用户静默上传论文。网站转换结果只是辅助文本，不能代替 PDF 核对。

### 1.2 另行确认保存位置

保存位置不计入上述四个材料路径。询问：

> 最终 Markdown 保存在哪里？可以提供自定义绝对路径，也可以回复“默认”。

- 用户回复“默认”时，保存目录就是**实际解析到的 `SKILL.md` 所在目录**。
- 默认文件名是 `<论文PDF文件名去除扩展名>_研究级论文解读.md`。
- 用户提供以 `.md` 结尾的路径时，将其视为完整输出文件路径；提供目录时，在阶段 1 中提议默认文件名并请用户确认。
- 阶段 1 只回显拟保存路径，不创建最终文件。
- 输出文件已经存在时，不覆盖、不改名后静默保存；在阶段 1 明确列出冲突并询问新文件名或覆盖授权。

### 1.3 输入完整性

- 路径缺失时只补问缺失项，不重复询问已确认项。
- Markdown 缺失、不可读或明显不是同一篇论文时，阶段 1 报告问题并停止；用户修复前不得进入阶段 2。
- figures 为空或缺失时，询问是否允许在阶段 2 直接从 PDF 核对或提取图表；不得假装已读取 figures。
- 不因为四个路径已经给齐而自动进入阶段 2。

## 2. 阶段 1 需求对齐

阶段 1 的目标是确认可执行性、输出结构和必要选择，不是提前解读论文。

### 2.1 必须执行的检查

1. 完整读取所选 `SKILL.md`，以及它明确要求用于本任务的 references、templates、scripts 和 assets。
2. 检查 PDF 是否存在、可读、页数可识别，并抽查文本与渲染页面；不得仅以扩展名判断成功。
3. 检查 Markdown 是否存在、可读、编码正常，并盘点章节、公式、表格、脚注和图表引用是否有明显转换缺失。
4. 检查 figures 目录是否存在、文件是否可读、数量与格式如何，并将图号或文件名与 PDF、Markdown 初步对应。
5. 通过题名、作者、摘要开头、章节顺序和主要 Figure/Table 编号判断 PDF 与 Markdown 是否来自同一论文。
6. 检查拟保存路径是否可用、是否与已有文件冲突。此时不得写入最终 Markdown。
7. 记录本次用户 Prompt 与 Skill 的显式冲突；用户 Prompt 中明确要求优先，并说明处理方式，不得静默忽略 Skill。

阶段 1 可以盘点结构和完整性，但不得系统解释研究结论、形成完整评价或生成最终文档。

### 2.2 第一次实质回复的固定结构

只按以下四部分回复，然后停止：

#### A. 对任务的理解

简洁说明：

- 最终产出是什么；
- PDF、Markdown 和 figures 分别如何使用；
- 当前 Skill 对证据、深度、结构、语言和验证的核心约束；
- 拟保存的完整路径。

#### B. 预定 Markdown 结构

依据 `assets/templates/research-paper-analysis.md` 和论文实际研究设计，列出拟采用的一级、二级标题。删除与论文类型无关的分支，不得凭空增加论文不存在的模型、数据或检验。

#### C. 需要用户确认的事项

只询问会改变结构或质量的事项。先给出以下默认方案，让用户可以直接回复“按默认方案开始阶段 2”：

- 深度：研究级完整拆解；
- 语言：必须确认“中文、英文、中英文、其他”之一；默认建议中文为主并在专业术语首次出现时保留英文，用户回复“按默认方案”即视为明确确认；
- 重点：平衡覆盖研究问题、理论、方法、证据、贡献与局限；
- 外部资料：默认不扩展外部文献，只分析所给论文；
- figures：逐图分析核心图表，是否在 Markdown 中嵌入原图另行确认；
- 分析者评价：单独标记，不与作者观点混写。

只在用户要求或论文特征确实需要时，询问定制研究方向、特殊理论/识别重点、严格双语、外部文献对照、图片嵌入等选择。保存位置已经确认时不得重复询问。

用户选择“中英文”时，必须执行严格平行双语并完整读取 `references/language-and-abbreviation-policy.md`。在正文起草前集中确认材料中的全部缩写、英文全称、中文译名和首次及后续展示规则；不得用英文摘要代替全文英文。选择“其他”时确认具体语言、地区变体或文字体系，以及是单语还是与中文并列。

#### D. 文件检查结果

逐项报告：

- Skill 读取状态与实际 `SKILL.md` 路径；
- PDF 的读取状态、页数和明显异常；
- Markdown 的读取状态、结构与转换异常；
- figures 的读取状态、数量、格式和初步编号对应；
- PDF 与 Markdown 是否疑似一致；
- 拟输出路径及是否冲突；
- 缺失文件、路径错误或当前阻断项。

完成 A—D 后明确写出“等待用户确认，尚未进入阶段 2”，并立即停止。

## 3. 阶段 2 准入条件

必须同时满足以下条件：

1. Skill、PDF 和 Markdown 已成功读取；
2. figures 已读取，或用户明确同意用 PDF 直接核对图表；
3. 保存位置和文件名已确认且覆盖风险已解决；
4. 阶段 1 中影响结构的必要选择已确认；
5. 用户明确说“开始阶段 2”“可以开始”或同等明确授权。

“路径已提供”“收到”“继续检查”或补充文件均不构成阶段 2 授权。

## 4. 三类论文材料的职责

### Markdown

优先用于检索正文、定位章节、整理理论、假设、方法、结果和结论。将其视为便利副本，不视为最终权威文本。

### PDF

作为论文原始版本的核对依据，用于确认：

- 正式章节结构和页序；
- 公式及符号；
- 表格数值、表注和显著性标记；
- 图号、图题、图注和坐标；
- 脚注、附录、跨栏和复杂排版；
- Markdown 中疑似缺失、错序或乱码的内容。

关键结论不得只因 Markdown 中出现就视为核验完成。

### figures

逐图与正文、PDF 对应。每张核心图至少解释：

1. 横纵轴或主要组成元素；
2. 图中实际呈现的结果；
3. 作者希望该图支持的论点；
4. 它与核心研究问题的关系；
5. 异常、异质性、替代解释或限制；
6. 对应的 Figure/Table、Section 或页码。

只描述“图里有什么”不合格。无法识别轴、图例或编号时写明“论文中无法确认”。

## 5. 正式分析方法

### 5.1 先建立证据地图

在起草前内部建立“主张—证据—定位—判断主体”映射：

- 主张是什么；
- 证据来自 PDF、Markdown 还是 figure；
- 定位到 Section、Figure、Table、Equation、Appendix 或 PDF 页码；
- 属于作者陈述、证据直接支持、作者解释，还是分析者评价；
- 是否仍有无法确认之处。

不得把内部推理链或工作笔记原样暴露在最终文档中，但必须呈现足以复核的证据定位和判断依据。

### 5.2 重建论文论证链

至少回答：

- **Research Question**：作者真正要回答什么；
- **Motivation**：为什么值得研究；
- **Gap**：已有研究未解决什么；
- **Theory or Mechanism**：X 为什么可能影响 Y；
- **Design or Method**：作者如何获取能够回答问题的证据；
- **Results**：证据实际显示什么；
- **Contribution**：相对已有研究真正新增什么，而非照抄 introduction 的自我宣称；
- **Limits**：哪些结论被直接支持，哪些仍是解释或延伸。

### 5.3 按研究类型选择分支

- **因果实证**：解释 treatment、control、variation、识别假设、因果链条和主要威胁；不得只因使用回归就称为因果识别。
- **描述性或预测研究**：解释预测目标、评价指标、样本外验证和可迁移性；不得强行套用 DID、RCT 或 treatment/control。
- **理论或数学模型**：解释模型解决的问题、核心假设、变量、关键参数、均衡或命题的直觉及其在论证链中的作用。
- **实验研究**：解释处理设计、随机化、测量、依从性、效应大小和实验外推限制。
- **调查研究**：解释抽样、问卷构念、测量有效性、响应偏差和结论边界。
- **案例或定性研究**：解释案例选择、材料来源、过程追踪、替代解释和可推广范围。
- **综述或概念论文**：解释文献选择、分类框架、综合逻辑和遗漏风险，不虚构原始数据或识别策略。

### 5.4 结果不能只写显著性

对每项主要结果，在论文提供信息的范围内说明：

- 方向和大小；
- 统计意义与不确定性；
- 经济、理论或现实意义；
- 是否支持对应假设；
- 稳健性、异质性和机制证据；
- 最强替代解释和适用边界。

论文没有报告系数、样本量、置信区间或检验时，不得推算或补造；写明“论文中无法确认”。

### 5.5 严格区分判断主体

至少区分四类表述：

1. **作者陈述**；
2. **论文证据直接支持**；
3. **作者解释或机制推断**；
4. **分析者评价**。

作者自行承认的局限与分析者进一步识别的局限必须分栏或分节。分析者评价要说明依据，不能冒充作者原意。

## 6. 最终 Markdown 结构

以 `assets/templates/research-paper-analysis.md` 为基线，并根据论文类型调整。核心层次为：

1. 论文信息与阅读地图；
2. 研究问题、动机和文献缺口；
3. 核心论证链；
4. 理论、机制与假设；
5. 数据、研究设计与方法；
6. 主要结果、稳健性、异质性与机制证据；
7. Figure、Table 与 Equation 深入解读；
8. 实际贡献与证据边界；
9. 作者承认的局限与分析者评价；
10. 理论、实践及后续研究启示；
11. 术语表与证据定位索引。

不适用的部分删除或合并，不留下空标题。对非实证论文，不强行创建“数据”“回归结果”或“识别策略”等章节。

## 7. 深度与表达要求

- 默认交付研究级完整拆解，不做成摘要拼接。标准实证或理论论文通常应达到约 5,000—10,000 个中文字符；复杂论文可以更长。原文很短、属于评论文章或用户明确要求精简时可以缩短，并在交付说明中说明原因。
- 先解释直觉，再给技术细节。专业术语首次出现时采用“中文解释（English term, acronym）”。
- 公式使用 Markdown/LaTeX，并解释用途、核心变量、参数含义、关注参数和论证作用。
- Figure、Table 和 Equation 保持原论文编号；无法确认编号时不得自行编号为原文编号。
- 表格只用于真正需要横向比较的信息，不用表格压缩本应展开的论证。
- 重要概念可加粗，但不使用宣传性口号、夸大性结论或无证据的政策建议。
- 不大段复制论文原文；以准确转述和定位为主。
- 嵌入原图前必须确认图片嵌入和图注选择；可见图表图注及表格换行标点继续遵守 `references/layout-punctuation-policy.md`。
- 无法核实的内容统一标记为 **论文中无法确认**，不得自行补全。

## 8. 交付前验证

保存前逐项检查并修正：

1. Skill 明确要求是否全部覆盖；
2. 关键事实是否能在 PDF 或原始 Markdown 中定位；
3. Figure、Table、Equation、Section 和 Appendix 编号是否一致；
4. 数字、系数、样本量、日期、假设和引文是否被捏造或误抄；
5. Markdown 转换错误是否已通过 PDF 纠正；
6. 作者结论、证据支持、作者解释和分析者评价是否清楚区分；
7. 因果表述是否符合研究设计；
8. 主要图表是否完成逐项解释，而不是只做表面描述；
9. 标题层级、公式、表格、链接和本地图片路径是否可用；
10. 是否仍有占位符、未处理冲突或“论文中无法确认”事项。

最终只在用户确认的路径保存 Markdown。交付消息说明：

- 输出文件的完整路径；
- 实际使用的源文件；
- 无法解析或无法确认的内容；
- 是否完整通过 Skill 检查；
- Prompt 与 Skill 若有冲突，其位置和处理方式。
