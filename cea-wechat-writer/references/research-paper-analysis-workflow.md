# 两阶段论文解读工作流

本文件只适用于“论文解读”模式。公众号推文继续执行 `SKILL.md` 中的公众号写作流程。

## 目录

1. 输入与保存位置
2. 阶段 1 需求对齐
3. 阶段 2 准入条件
4. 三类论文材料的职责
5. 正式分析方法
6. 最终 Markdown 结构
7. 深度与表达要求
8. 交付前验证

## 1. 输入与保存位置

### 1.1 首轮只收集四个绝对路径

按顺序询问并回显：

1. **Skill 目录**：含 `SKILL.md` 的目录；若用户给出上级目录，则在其内部定位 `SKILL.md`。发现多个候选时让用户选择，不得擅自决定。
2. **论文 PDF**：原始论文 PDF 的绝对路径。
3. **论文 Markdown**：由同一份论文转换得到的 `.md` 文件绝对路径。
4. **论文 figures 目录**：从论文提取的图片目录绝对路径；确实没有时允许用户回复“无”。

如果当前调用已经明确指定 Skill 路径，回显该路径并请求确认即可，不要求用户再次粘贴。

询问论文 Markdown 时必须同时提示：

> 如果尚未生成论文 Markdown，请先使用 [MarkItDown Online](https://markitdown.online/) 将 PDF 转换为 Markdown，下载到本地后提供 `.md` 文件的绝对路径。PDF 涉及未公开、受版权或保密限制的内容时，请先确认是否允许上传第三方网站。

不得替用户静默上传论文。网站转换结果只是辅助文本，不能代替 PDF 核对。

### 1.2 另行确认保存位置

保存位置不计入上述四个材料路径。询问：

> 论文解读正文和编辑核查记录保存在哪里？可以提供自定义绝对路径，也可以回复“默认”。

- 用户回复“默认”时，保存目录就是**实际解析到的 `SKILL.md` 所在目录**。
- 默认生成两个文件：读者正文 `<论文PDF文件名去除扩展名>_论文解读.md`，以及仅供作者和编辑使用的 `<论文PDF文件名去除扩展名>_编辑核查记录.md`。
- 用户提供以 `.md` 结尾的路径时，将其视为完整输出文件路径；提供目录时，在阶段 1 中提议默认文件名并请用户确认。
- 用户只指定正文文件名时，编辑核查记录默认保存在同一目录，并使用相同文件名前缀加 `_编辑核查记录.md`。
- 阶段 1 只回显两个拟保存路径，不创建文件。
- 任一输出文件已经存在时，不覆盖、不改名后静默保存；在阶段 1 明确列出冲突并询问新文件名或覆盖授权。

### 1.3 输入完整性

- 路径缺失时只补问缺失项，不重复询问已确认项。
- Markdown 缺失、不可读或明显不是同一篇论文时，阶段 1 报告问题并停止；用户修复前不得进入阶段 2。
- figures 为空或缺失时，询问是否允许在阶段 2 直接从 PDF 核对或提取图表；不得假装已读取 figures。
- 不因为四个路径已经给齐而自动进入阶段 2。

## 2. 阶段 1 需求对齐

阶段 1 的目标是确认可执行性、输出结构和必要选择，不是提前解读论文。

### 2.1 必须执行的检查

1. 完整读取所选 `SKILL.md`，以及它明确要求用于本任务的 references、templates、scripts 和 assets。
2. 检查 PDF 是否存在、可读、页数可识别，并抽查文本与渲染页面；不得仅以扩展名判断成功。
3. 检查 Markdown 是否存在、可读、编码正常，并盘点章节、公式、表格、脚注和图表引用是否有明显转换缺失。
4. 检查 figures 目录是否存在、文件是否可读、数量与格式如何，并将图号或文件名与 PDF、Markdown 初步对应。
5. 通过题名、作者、摘要开头、章节顺序和主要 Figure/Table 编号判断 PDF 与 Markdown 是否来自同一论文。
6. 检查两个拟保存路径是否可用、是否与已有文件冲突。此时不得写入最终文件。
7. 记录本次用户 Prompt 与 Skill 的显式冲突；用户 Prompt 中明确要求优先，并说明处理方式，不得静默忽略 Skill。

阶段 1 可以盘点结构和完整性，但不得系统解释研究结论、形成完整评价或生成最终文档。

### 2.2 第一次实质回复的固定结构

只按以下四部分回复，然后停止：

#### A. 对任务的理解

简洁说明：

- 最终产出是什么；
- PDF、Markdown 和 figures 分别如何使用；
- 当前 Skill 对证据、深度、结构、语言和验证的核心约束；
- 正文和编辑核查记录的拟保存完整路径。

#### B. 预定 Markdown 结构

依据 `assets/templates/research-paper-analysis.md` 和论文实际研究设计，提出少量、宽口径的正文结构。默认只列 4—6 个二级标题，通常不预设三级标题；相邻内容应合并，不得为了覆盖清单把一个连续观点拆碎。删除与论文类型无关的分支，不得凭空增加论文不存在的模型、数据或检验。

#### C. 需要用户确认的事项

只询问会改变结构或质量的事项。先给出以下默认方案，让用户可以直接回复“按默认方案开始阶段 2”：

- 深度：重点导向的完整解读，默认篇幅适中，不逐节复述；
- 语言：必须确认“中文、英文、中英文、其他”之一；默认建议中文为主并在专业术语首次出现时保留英文，用户回复“按默认方案”即视为明确确认；
- 重点：平衡覆盖研究问题、理论、方法、证据、贡献与局限；
- 外部资料：默认不扩展外部文献，只分析所给论文；
- figures：只选真正支撑主线的核心图表深入分析，是否在 Markdown 中嵌入原图另行确认；
- 判断归属：正文用自然主语区分作者观点、论文证据和编辑判断，详细映射放入编辑核查记录，不使用可见标签。

只在用户要求或论文特征确实需要时，询问定制研究方向、特殊理论/识别重点、严格双语、外部文献对照、图片嵌入等选择。保存位置已经确认时不得重复询问。

用户选择“中英文”时，必须执行严格平行双语并完整读取 `references/language-and-abbreviation-policy.md`。在正文起草前集中确认材料中的全部缩写、英文全称、中文译名和首次及后续展示规则；不得用英文摘要代替全文英文。选择“其他”时确认具体语言、地区变体或文字体系，以及是单语还是与中文并列。

#### D. 文件检查结果

逐项报告：

- Skill 读取状态与实际 `SKILL.md` 路径；
- PDF 的读取状态、页数和明显异常；
- Markdown 的读取状态、结构与转换异常；
- figures 的读取状态、数量、格式和初步编号对应；
- PDF 与 Markdown 是否疑似一致；
- 正文与编辑核查记录的拟输出路径及是否冲突；
- 缺失文件、路径错误或当前阻断项。

完成 A—D 后明确写出“等待用户确认，尚未进入阶段 2”，并立即停止。

## 3. 阶段 2 准入条件

必须同时满足以下条件：

1. Skill、PDF 和 Markdown 已成功读取；
2. figures 已读取，或用户明确同意用 PDF 直接核对图表；
3. 正文与编辑核查记录的保存位置和文件名已经确定，覆盖风险已解决；
4. 阶段 1 中影响结构的必要选择已确认；
5. 用户明确说“开始阶段 2”“可以开始”或同等明确授权。

“路径已提供”“收到”“继续检查”或补充文件均不构成阶段 2 授权。

## 4. 三类论文材料的职责

### Markdown

优先用于检索正文、定位章节、整理理论、假设、方法、结果和结论。将其视为便利副本，不视为最终权威文本。

### PDF

作为论文原始版本的核对依据，用于确认：

- 正式章节结构和页序；
- 公式及符号；
- 表格数值、表注和显著性标记；
- 图号、图题、图注和坐标；
- 脚注、附录、跨栏和复杂排版；
- Markdown 中疑似缺失、错序或乱码的内容。

关键结论不得只因 Markdown 中出现就视为核验完成。

### figures

逐图与正文、PDF 对应。先判断图表是否会改变读者对主线的理解，只把必要的核心图写入正文。对入选图表内部检查：

1. 横纵轴或主要组成元素；
2. 图中实际呈现的结果；
3. 作者希望该图支持的论点；
4. 它与核心研究问题的关系；
5. 异常、异质性、替代解释或限制；
6. 对应的 Figure/Table、Section 或页码。

不要在正文中机械逐项回答这六个问题，而要把有关信息组织成一段连贯解释。只描述“图里有什么”不合格。无法识别轴、图例或编号时，在编辑核查记录中登记；如果会影响正文结论，再自然说明论文没有提供或当前材料无法辨认。

## 5. 正式分析方法

### 5.1 先建立证据地图

在起草前内部建立“主张—证据—定位—判断主体”映射，并写入 `<论文PDF文件名去除扩展名>_编辑核查记录.md`：

- 主张是什么；
- 证据来自 PDF、Markdown 还是 figure；
- 定位到 Section、Figure、Table、Equation、Appendix 或 PDF 页码；
- 属于作者陈述、证据直接支持、作者解释，还是编辑判断；
- 是否仍有无法确认之处。

不得把内部推理链、分类标签或工作笔记原样暴露在读者正文中。正文使用自然主语和必要的 Section、Figure、Table、Equation 或页码说明归属；完整状态与判断依据保留在编辑核查记录。

### 5.2 重建论文论证链

内部至少回答以下问题，但不要把英文术语或问题清单机械复制成正文标题：

- **Research Question**：作者真正要回答什么；
- **Motivation**：为什么值得研究；
- **Gap**：已有研究未解决什么；
- **Theory or Mechanism**：X 为什么可能影响 Y；
- **Design or Method**：作者如何获取能够回答问题的证据；
- **Results**：证据实际显示什么；
- **Contribution**：相对已有研究真正新增什么，而非照抄 introduction 的自我宣称；
- **Limits**：哪些结论被直接支持，哪些仍是解释或延伸。

### 5.3 按研究类型选择分支

- **因果实证**：解释 treatment、control、variation、识别假设、因果链条和主要威胁；不得只因使用回归就称为因果识别。
- **描述性或预测研究**：解释预测目标、评价指标、样本外验证和可迁移性；不得强行套用 DID、RCT 或 treatment/control。
- **理论或数学模型**：解释模型解决的问题、核心假设、变量、关键参数、均衡或命题的直觉及其在论证链中的作用。
- **实验研究**：解释处理设计、随机化、测量、依从性、效应大小和实验外推限制。
- **调查研究**：解释抽样、问卷构念、测量有效性、响应偏差和结论边界。
- **案例或定性研究**：解释案例选择、材料来源、过程追踪、替代解释和可推广范围。
- **综述或概念论文**：解释文献选择、分类框架、综合逻辑和遗漏风险，不虚构原始数据或识别策略。

### 5.4 结果不能只写显著性

对每项主要结果，在论文提供信息的范围内说明：

- 方向和大小；
- 统计意义与不确定性；
- 经济、理论或现实意义；
- 是否支持对应假设；
- 稳健性、异质性和机制证据；
- 最强替代解释和适用边界。

论文没有报告系数、样本量、置信区间或检验时，不得推算或补造；在编辑核查记录中登记。只有缺失信息会影响理解时，才在正文中自然说明论文没有报告该项。

### 5.5 自然区分判断主体

内部证据地图仍须区分作者陈述、论文证据直接支持、作者解释和编辑判断，但这些词不得作为读者正文中的标题、标签、表格字段或段首前缀。

用具体主语和证据动词自然说明归属，例如：“作者在 Proposition 3 中提出……”“Figure 4 显示……”“作者据此解释为……”“把命题与图放在一起看，两处并不完全一致，因此更稳妥的理解是……”。

作者自行承认的局限与编辑进一步识别的边界可以在同一节连续讨论，不必强制分栏或分节。编辑判断必须紧接依据，不能冒充作者原意；详细分类、支持程度和处理决定写入编辑核查记录。

## 6. 最终 Markdown 结构

以 `assets/templates/research-paper-analysis.md` 为基线，并根据论文类型与内容重新命名标题。正文通常只保留 4—6 个二级标题：

1. 自然开篇，直接交代论文在问什么以及主要结论；
2. 问题从何而来，以及作者的核心思路；
3. 作者如何回答，包括理解结论所需的理论、数据或方法；
4. 最值得关注的发现，把必要图表和公式就地解释；
5. 如何理解这些发现，包括真正贡献、证据边界和最重要的未决问题；
6. 必要时用很短的结语或原文定位收束。

这只是内容顺序，不是必须逐字采用的标题。默认不用三级标题；一个小节只有一小段时与相邻内容合并。对非实证论文不创建“数据”“回归结果”或“识别策略”等无关章节。证据状态表、判断主体表、完整术语表和流程说明进入编辑核查记录，不进入读者正文。

## 7. 深度与表达要求

- 默认交付重点导向、首尾连贯的完整解读，不做逐节摘要拼接。中文正文通常约 3,000—5,000 个中文字符，复杂论文一般不超过约 6,000 个中文字符；需要更长时先征得用户同意。原文较短时可以更短，不为达到字数补写无关内容。
- 只选择会影响核心论证的理论、方法、结果、稳健性、异质性和图表。不要为了显得全面而罗列所有检验、附录或次要结果。
- 写作前和交付前都读取 `references/natural-writing-and-clean-copy.md`。删除填充句、重复总结、机械排比、过度粗体、连续“标签＋冒号”列表以及解释 Prompt 或 Skill 的元话语。
- 默认正文只有少量宽口径标题。段落按论文论证顺序自然过渡，不把一个连续观点切成多个一段式小节。
- 先解释直觉，再给技术细节。专业术语首次出现时采用“中文解释（English term, acronym）”。
- 公式使用 Markdown/LaTeX，并解释用途、核心变量、参数含义、关注参数和论证作用。
- Figure、Table 和 Equation 保持原论文编号；无法确认编号时不得自行编号为原文编号。
- 表格只用于真正需要横向比较的信息，不用表格压缩本应展开的论证。
- 重要概念可加粗，但不使用宣传性口号、夸大性结论或无证据的政策建议。
- 不大段复制论文原文；以准确转述和定位为主。
- 嵌入原图前必须确认图片嵌入和图注选择；可见图表图注及表格换行标点继续遵守 `references/layout-punctuation-policy.md`。
- 无法核实的内容不得自行补全。详细状态写入编辑核查记录；只有在它影响读者理解时，才在正文中自然写明“论文没有报告……”或“现有材料不足以判断……”，不使用机械状态标签。

## 8. 交付前验证

保存前逐项检查并修正：

1. Skill 明确要求是否全部覆盖；
2. 关键事实是否能在 PDF 或原始 Markdown 中定位；
3. Figure、Table、Equation、Section 和 Appendix 编号是否一致；
4. 数字、系数、样本量、日期、假设和引文是否被捏造或误抄；
5. Markdown 转换错误是否已通过 PDF 纠正；
6. 作者结论、证据支持、作者解释和编辑判断是否通过自然主语清楚区分，详细映射是否保存在编辑核查记录；
7. 因果表述是否符合研究设计；
8. 入选的主要图表是否说明了它对核心论证的作用，而不是只做表面描述；
9. 标题是否过多、段落是否碎裂，公式、表格、链接和本地图片路径是否可用；
10. 正文是否出现“研究级解读”“已确认事项”“作者陈述”“证据直接支持”“分析者评价”“核验状态”或机器审核状态等工作流标签；
11. 是否仍有占位符、未处理冲突或无法确认事项，这些内容是否完整登记在编辑核查记录。

最终只在用户确认的路径保存两个 Markdown。读者正文使用 `assets/templates/research-paper-analysis.md`，编辑核查记录使用 `assets/templates/research-paper-analysis-editor-review.md`。交付消息说明：

- 两个输出文件的完整路径及用途；
- 实际使用的源文件；
- 无法解析或无法确认的内容；
- 是否完整通过 Skill 检查；
- Prompt 与 Skill 若有冲突，其位置和处理方式。
