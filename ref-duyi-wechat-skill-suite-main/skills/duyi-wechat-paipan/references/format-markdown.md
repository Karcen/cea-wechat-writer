# 公众号排版格式规范

用于把一篇已写好的文章排成适合微信手机端阅读的 Markdown / WeChat-ready HTML。

## 核心边界

- 用户只说排版、配图、发布、手机预览时，正文视为锁定。
- 不改句子、用词、解释密度、事实、案例、论证顺序和结尾。
- 只调整标题层级、段落换行、强调、引用、图片槽位、前后留白和 HTML 样式。
- 需要润色、重写、补充解释时，必须等用户明确授权。

## 排版蓝图

完整文章排版前，先生成 `{filename}-paipan-analysis.md`，作为排版蓝图。蓝图只服务排版判断，不进入最终正文。

蓝图包含：

- 读者读完后应获得的主线理解。
- 自然分节位置：话题、场景、论证层变化处。
- 需要拆开的长段落。
- 适合单独成行的关键转折句。
- 值得加粗或标记的重点句。
- 适合放图片、截图或视觉停顿的位置。
- 从 16 个正式中文意象风格中选择的 CSS 风格和理由。

## 正式风格

风格选择以 `duyi-wechat-css-layer/templates/styles.md` 为准，只使用以下 16 个正式风格：

```text
白瓷 / 蓝图 / 紫线 / 墨线 / 陶土 / 宣纸 / 朱批 / 杏纸 / 素纸 / 萤石 / 霓虹 / 橙陶 / 朱砂 / 金箔 / 竹简 / 青笺
```

选择原则：

- 没有明确视觉要求时，按文章气质选择；没有明显倾向时用 `白瓷`。
- 商业判断、趋势分析、强观点文章可用 `朱批`、`杏纸`、`素纸`。
- AI 研究、方法论、温和解释可用 `陶土`、`宣纸`、`蓝图`。
- 产品、工具、技术、发布说明可用 `蓝图`、`墨线`、`霓虹`。
- 个人记录、随笔、金句、轻教程可用 `金箔`、`竹简`、`青笺`。
- 重点标记使用 `==text==`，只标真正重要的判断、结论、数据或行动点。

## Markdown 规则

- `##` 只用于真实章节转折，不要每隔几段强行加标题。
- `###` 或加粗小标题用于局部转折，如“说白了”“我的理解”“换句话说”。
- 引用只用于金句、判断、原话或强提醒，不做普通装饰。
- 加粗只用于结论，不做视觉堆叠。
- 列表只在原文存在并列关系、步骤或清单时使用。
- 表格只用于真实比较、矩阵或参数对照。
- 文件路径、命令、产品名和代码词保持反引号。
- 精确数字、日期、人名、产品名和技术术语必须保留。
- 不新增未经原文支持的事实、例子和结论。

## 手机端节奏

- 一个短段落只说一件事。
- 一个想法可以拆成多个短句。
- 重要转折单独成行。
- 连续密集段落之间加入小标题、图片槽位或视觉停顿。
- 段落尽量控制在手机端一屏内能轻松扫读的长度。

## 图片槽位

图片只承担三种功能：

- 帮读者更快理解概念。
- 提供证据、截图或过程可信度。
- 在长逻辑后给读者一个视觉停顿。

不要为了填版面添加装饰图。源文已有图片时，除非阅读流明显需要调整，否则保留原位置。

## HTML 输出

生成 WeChat-ready HTML 时使用：

```bash
python3 ~/.agents/skills/duyi-wechat-paipan/scripts/render_wechat_html.py input.md --style 白瓷 --output article-wechat.html
```

需要本地手机预览时加 `--standalone`：

```bash
python3 ~/.agents/skills/duyi-wechat-paipan/scripts/render_wechat_html.py input.md --style 青笺 --standalone --output article-青笺-preview.html
```

交给发布流程前，必须确认 HTML QA gate 通过。
