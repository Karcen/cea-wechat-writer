# 公众号排版 QA Checklist

排版、预览、生成 WeChat-ready HTML 或进入发布前执行。

## 正文完整性

- 如果请求只是排版、配图、发布或手机预览，正文已经锁定。
- 没有改写句子、增删解释、调整事实、替换案例或改变论证顺序。
- 标题只有在用户明确要求标题工作时才调整。
- 数字、日期、人名、产品名、路径、命令和技术术语保持一致。

## 排版蓝图

- 完整文章已有 `{filename}-paipan-analysis.md`。
- 蓝图包含主线理解、自然分节、长段落拆分、单独成行句、强调候选、图片/停顿点和 CSS 风格选择。
- 排版稿遵循蓝图；如有偏离，偏离原因清楚。
- 只做展示层处理时，标题和标记没有创造新观点。

## 手机阅读

- 首屏标题、导语和正文密度舒适。
- 段落足够短，手机端不压迫。
- 长逻辑之间有小标题、独立转折句、图片槽位或留白。
- 文本不溢出、不重叠、不被裁切。

## CSS 风格

- 只使用 16 个正式中文意象风格：白瓷、蓝图、紫线、墨线、陶土、宣纸、朱批、杏纸、素纸、萤石、霓虹、橙陶、朱砂、金箔、竹简、青笺。
- 风格与文章气质匹配；没有明确倾向时使用 `白瓷`。
- `青笺`正文左对齐、黑字为主，只把关键重点做浅绿底强调。
- `==text==` 只用于真正重要的判断、结论、数据或行动点。
- 同一篇文章不混用多套 CSS 主风格。

## 图片和徽标

- 图片用于理解、证据或视觉停顿，不做纯装饰。
- 原文图片位置没有被无理由移动。
- 如果启用公开记录徽标，它位于标题后、首图后或第一正文段前的自然位置。
- 预览和草稿创建不递增公开记录计数；只有用户确认已发布后才递增。

## WeChat HTML

- WeChat HTML 使用内联样式，并包含 `#output` wrapper。
- 渲染链路为 Markdown parser -> 语义 HTML -> theme CSS -> CSS 内联 -> 微信兼容后处理 -> QA gate。
- 最终微信片段不包含 `class`、`data-*` 或 `<style>`。
- HTML 不包含字面量 `\n`；只允许真实换行。
- Markdown 语义保留：分割线、列表、嵌套列表、表格和公式都正确渲染。
- 公式不残留裸 `$$`、`\text`、`\times`、`\rightarrow` 或 `\underbrace`。
- 正文段间距和行高在 WeChat HTML 中可读，不只是在本地预览里好看。
- 完整发布流程先跑 dry-run，再创建草稿。
- 本地预览不是最终证明；微信草稿或手机预览是最终检查。
